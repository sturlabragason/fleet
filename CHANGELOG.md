# What's new in fleet

User-facing changes, newest first. `fleet changes` and `Alt-g` show this file; it is built into the binary.

To add an entry: one line under today's `## YYYY-MM-DD` heading (add the heading if it is missing), at the top of that day, in the same commit as the change. Say what the user can do now, not how it was built. End with the ADR or commit in brackets when there is one: `(ADR-27)`, `(66a2ece, ADR-27)`.

## 2026-11-06
- Safer agents and squads: every effort level, `light` included, now tells the agent never to push, to credit AI with `Assisted-by:` and never a `Co-authored-by:`, to edit nothing on a read-only task and to commit on its own `fleet/` branch, never main. Closing a squad leader hands its squad's unread reports to you instead of dropping them, leaves a team of yours with the same name alone, a peer message no longer swallows a squad report's wake, and a leader's `fleet close/send/park/wake` act only on its own squad (ADR-59)
- Agents start on the newest Claude: the built-in `claude` profile now runs `--model opus` with its subagents on `sonnet` (the claude CLI resolves both to the newest model), and `claude-copilot` runs `claude-opus-5.5` instead of `claude-opus-5`. A profile you defined in `~/.fleet/tools.toml` keeps its own `--model`, so check it (ADR-58)
- A squad leader works from turn one: its first prompt now names its `fleet_squad_*` tools and what each is for, says its agents report to it and that it must not spawn through the `fleet` CLI, and `fleet spawn` run from inside a leader's pane puts the new agent in that leader's squad instead of creating a sibling that reports to the admiral. Fields a newer fleet writes to the board (`leader`, `effort`, …) also survive a `fleet watch` left running from an older build, which is how a leader silently lost its squad tools — restart the fleet once for that fix to take effect (ADR-58)

## 2026-11-05
- Small jobs stop getting the whole process: a spawn now picks how much worker playbook its agent is given with `fleet spawn --effort light|standard|pro` (or `effort` on `fleet_spawn` and `fleet_squad_spawn`). `light` is five lines for an errand or a quick question, `standard` adds a plan, build-and-test and a commit, `pro` is the full checklist. Without `--effort`, a spawn into a git repo with a worktree still gets `pro` and anything else gets `light` — so `--no-worktree` work that must land in your own checkout now wants `--effort pro` too. `fleet playbook --effort LEVEL` shows any of them (ADR-57)
- One line stops every agent asking for permission: `mode = "auto"` under `[defaults]` in `~/.config/fleet/config.toml`. `auto` is now a mode every profile knows, mapped to that tool's own allow-all flag (Copilot `--allow-all --autopilot`, Claude Code `--permission-mode bypassPermissions`, agy `--dangerously-skip-permissions`, vibe `--auto-approve`), so an agy agent no longer stops on "Run this command?" while your Copilot agents run unattended. agy and vibe also gain `accept-edits`/`plan` and `smart-approve`/`ask` modes. Nothing changes unless you set the key (ADR-56)
- Pick a TUI colour theme: `theme = "stealth"` (or `"neon-drive"`, `"phosphor"`, `"graphite"`) under `[defaults]` in `~/.config/fleet/config.toml`, then run `fleet up` again — the tmux chrome re-colours and the overview restarts, your agents keep running. The default is unchanged, so nothing moves unless you set the key (ADR-55)
- `scripts/check-renders.sh page.html` proves a page actually renders before you hand it over: it copies the file alone into an empty directory, the way a sandboxed browser's document portal does, loads it headless and fails if any image did not decode. `xdg-open` exits 0 for a blank page, so opening one was never evidence
- `scripts/inline-html.py page.html out.html [--embed-pages]` folds a page's images, stylesheets and sibling HTML into one self-contained file, so a mockup you hand someone still renders in a sandboxed browser instead of showing broken images
- Spawn a leader and it runs its own squad: `fleet spawn --leader <name> <profile>` (or `fleet_spawn` with `leader: true`) gives that agent squad tools to spawn, watch, message, read the reports of and close up to 4 agents of its own. Their reports wake the leader, not you; you get the leader's one summary. `fleet_status` and the wall show who leads whom (`▲`), `fleet close <leader> --squad` takes the squad with it, and `[squad] max_members` / `max_depth` set the caps (ADR-53)
- The overview never leaves ghost tiles behind: closing several agents at once (or resizing the window) used to leave a row of half-drawn tiles and the reports of agents that were already gone; every frame now fills the pane, so the old rows are always overwritten (ADR-54)
- Fake agents print work you can read: a task line, the reads, edits and test runs it would take, an approval it wants and a summary when it finishes, under one footer that is redrawn in place instead of a new "Thinking… step N" line every tick. Hold one in a state with `fleet send <name> "!work"`, `"!wait"`, `"!error"` or `"!done"`, each with an optional task name (ADR-52)
- The README screenshot and `docs/img/demo.gif` show a believable fleet: a 2×2 wall of one agent working, one waiting on your approval, one failed and one done, an admiral reporting what it did, and no browser-window decoration. `scripts/screenshot.sh` composes it, so it can be regenerated the same way after a layout or palette change (ADR-52)
- Agents spawned in the same second no longer all pick the same fake task: the name, the pid and the clock are hashed together for the seed
- Agent reports always wake the admiral again: a report that lands while the admiral is busy is typed in as soon as its pane goes idle — the watcher retries it with no overview open — and a second report wakes it even when it has not read the first one. A wake that cannot be typed is kept and retried, never dropped, and says so in the log (ADR-51)
- Agents never stop on "Do you trust this folder?" again: fleet marks an agent's dir as trusted in the tool's own config (Claude, Copilot CLI, vibe) before starting it, answers the dialog on screen for tools it cannot pre-mark, and `auto_trust = false` in config.toml gives you the prompt back (ADR-47)
- Fleet never starts an agent in your home directory: a spawn or adopt there runs in `~/.fleet/scratch/<name>` instead, and the reply says so — no more tools warning they are in a dangerous folder, and no agent reading every dotfile in `$HOME` as project config (ADR-47)
- Agent status stays right with no window open: `fleet up` starts a watcher that refreshes within about a second, and within 200 ms when a Claude hook or a session log fires, so pane border titles, `fleet ls`, the board and the admiral never disagree or lag (ADR-49)
- Trust and permission dialogs with no numbers on screen (Claude's "Is this a project you trust?", "Allow external CLAUDE.md file imports?") now read as **waiting** with the question as `waiting_for`, and the admiral can answer them: `fleet_answer` takes `label="Yes, allow"` as well as `option=N` (ADR-49)
- `fleet adr claim` takes the next free ADR number for DESIGN.md §14 atomically, so parallel agents never pick the same one; `fleet adr ls` shows the live claims, `fleet adr release N` gives one back, and a claim frees itself once its ADR is on main. The admiral can claim one for a spawn prompt with `fleet_adr` (ADR-50)
- `fleet merge` finishes a branch for you: it rebases onto main, runs the checks, merges into your local main (fast-forward when it can) and runs the checks again there. A `CHANGELOG.md` or `DESIGN.md` conflict keeps both sides in that file's own order — your changelog line on top, your ADR at the bottom of §14 — instead of stopping you; any other conflict aborts cleanly and names the file and the other worktree. `--dry-run` shows the order first. It never pushes and never removes your worktree (ADR-48)
- `fleet reports [--all] [--limit N] [--as NAME]` reads agent reports from a shell, the same history the admiral's `fleet_reports` shows: unread ones oldest first, `--all` for the last N. Reading from an agent pane or with `--as NAME` leaves them unread, so a worker can catch up without taking the admiral's reports
- `fleet park <name>` (and `fleet_park` for the admiral) stops an idle agent's process to free its 300-450 MB but keeps it on the board with its session; `fleet wake <name>` picks the conversation up where it stopped (ADR-44)
- Fleet watches free memory: under `[memory] min_free` (default 4 GB) it parks the longest-idle agent — never a pinned, working or waiting one — queues new spawns until memory returns, and tells the admiral. `guard = false` in config.toml turns it off (ADR-44)
- `max_working` and the new `[memory]` settings are re-read from config.toml while fleet runs, so you can retune a busy fleet without restarting it, and queued agents now also start when the overview TUI isn't running (ADR-44)
- `fleet spend` shows what each agent has cost so far and the fleet-wide total — AI credits for Copilot agents, tokens for Claude — read from the agents' own session files with no model call; the same figure is a column in the admiral's `fleet_status` and a line in `fleet info` (ADR-46)
- Agents no longer stall waiting on a coordinator: merge order is read from branch state, each agent is given its ADR number when it is spawned, and the CHANGELOG and DESIGN conflicts every batch produces are resolved by keeping both sides. Closing an agent now checks its unread reports and inbox first, so a late hand-off isn't lost
- Agents that grind are called out: an agent goes **stuck** (red) when the same error banner comes back twice in a row, or when it has been working with no screen change for `stuck_after` (default 10m), and the admiral is told once per episode. Nothing is paused or killed; `stuck_action = "interrupt"` in config.toml opts into sending one Escape (ADR-45)
- vibe agents started in your home directory no longer read as `error` forever: its "WARNING: You are in the home directory" startup banner is a warning, not a failure (ADR-45)
- A spawn can carry a task card: `fleet spawn --goal "…" --check "make test" --check-exit 0 --result result.md` (and the same arguments on `fleet_spawn`) tells the agent its goal and where to write `result.md`, shows it on the tile and in `fleet info`, and when the agent reports done fleet runs the check itself in the agent's dir and tells the admiral whether it passed — an agent whose check fails is not auto-closed (ADR-43)
- Fleet reads claude, agy and vibe properly: they now show working and error instead of looking idle while they think, and a report wake can type into their prompt box like it already could into Copilot's (ADR-42)
- `fleet snap <agent> <state>` saves an agent's pane as a status fixture, so teaching fleet a new tool's screens is a capture rather than a hand-written one (ADR-42)
- The overview header shows unread agent reports as a `✉ N reports` badge, so you can see reports are waiting without looking at the status line; it clears when you read them (ADR-36)
- Wall panes never shrink past readable: the minimum pane size scales with your terminal, so `M-9` on a laptop puts up four panes instead of nine, an add that would not fit says so, and resizing the terminal sheds panes rather than crushing them — pinned and waiting panes are never the ones to go (ADR-41)
- `fleet peek --summary <name>` and the admiral's `fleet_peek(summary=true)` give about 5 lines from a cheap model — what the agent is doing, what it waits for, any error — instead of screen text. It runs on the Copilot CLI you are already signed in to (no API key), caches per screen, calls at most once per agent per 30s and fails open; `[summary]` in config.toml picks the model (default Haiku 5.5) or turns it off (ADR-40)
- Worker agents are told to stay in the worktree fleet spawned them in and to leave it and its branch behind after merging, instead of creating one by hand and deleting their own working directory at the end (ADR-39)
- Spawning an agent into a git repo gives it its own worktree, `<repo>.wt/<name>` on branch `fleet/<name>`, so parallel agents never share one checkout; `fleet close` and the idle sweep name that worktree and branch when work is left in it, and `--no-worktree`, `worktree = false` in config.toml or `worktree: false` on `fleet_spawn` opt out (ADR-39)
- Drag-select, double-click and triple-click now copy from any agent pane, including the admiral, straight to the system clipboard, so `Ctrl+Shift+V` pastes what you just selected (ADR-38)
- The wall and overview tell focus, selection and the ▶ target apart at a glance: only the ▶ target is lavender, the overview cursor is an underline in the agent's status colour, the pane you are typing in has a bright border while the others dim one step, and `· next out` recedes (ADR-37)
- Spawned agents and the admiral are told that time matters: avoidable time is not spent, and an earlier correct result is better
- Spawned agents squash fixup commits into their logical commits on their branch before merging, so published history stays one reviewable commit per change and is never rewritten
- Past 14 agents the overview keeps every agent clickable: agents that need you keep full cards, the rest become one-line rows, idle ones fold into `+N idle`, the wheel scrolls, and cards no longer move for 3 seconds after you click or press a key (ADR-32)
- Right-click a card for a menu (put in ▶, add, preview, pin, take off); `Space` previews an agent live in a popup, `u` undoes a replace, `p` pins a pane so it is never replaced (ADR-31)
- Click a wall pane to mark it `▶`, then click a card: that agent takes the `▶` pane, whether or not the wall is full. `a` adds a pane instead, `Tab` or `Alt-n` sends the next waiting agent there, `Esc` clears it, and clicking no longer resizes or moves other panes (ADR-31)
- Agent reports no longer land in text you are typing to the admiral: fleet types the wake line only into an empty, quiet input box, presses Enter only when the box holds exactly that line, sends one line for several reports, and shows unread reports on the status line (✉ N reports) (ADR-36)
- Agents end their reports with `next:`, `risks:`, `decisions:` and `retro:` lines, escalate blockers early, keep to their scope and leave merge order to a named coordinator; the admiral keeps risks, assumptions, issues and decisions in its notes. Why: docs/process.md (ADR-35)
- Agents in the same team, or the same repo when they have no team, message each other without asking; `agent_mail` in config.toml picks `team`, `open` or `ask`, and `fleet access log` shows every message (ADR-34)
- Agents you end with `/exit` close by themselves; crashed ones are reported to the admiral with their exit code and close after `dead_pane_grace` (default 5m), with a note when they left work behind (ADR-33)
- What's new view: `Alt-g`, `g` in the overview and `fleet changes` show fleet's own new features, whichever pane they are opened from, and mark the ones you have not seen yet (ADR-30)
- Agents that report done close themselves unless they left their own work behind, also read-only ones in a dirty checkout; reports to a busy admiral wait until it is idle; `auto_close_idle` also closes done agents once their work is merged (19456fb, ADR-29)
- Text you copy in tmux copy-mode lands on the system clipboard (94c7ac4, ADR-28)
- Pick the admiral's CLI with `Alt-P` or `fleet admiral profile`; a swap hands off to the new one, a restart under the same profile resumes the chat in place (66a2ece, ADR-27)
- The supervisor is now the admiral; `fleet supervisor ...` and the old env names keep working (f5b2bd8, ADR-26)
- Brand style guide and logo marks in the README (0066bec)
- The admiral's MCP server hot-reloads in place after `make build`, so new tools arrive without losing the chat (faa78ab, ADR-25)
- At most 4 agents work at once (`max_working`); further spawns wait in a queue and start in order (1e24fb4, ADR-23)
- Every spawned agent gets the worker playbook with its prompt; `fleet touching <files>` says whether another worktree is changing them (4b8c253, ADR-22)
- CPU cap: `env` in `config.toml` sets `GOMAXPROCS`/`GOFLAGS` for agent panes, so parallel builds don't take every core (e14eef0, ADR-23)
- The overview gives every agent a card, also beyond 5 agents, wrapped and sized to the pane (ecf9f56)
- New docs: prior-art survey (`docs/prior-art.md`) and measured RAM/CPU per agent (`docs/perf.md`) (e7f3013, a205a9e)
- Subagents show as status-coloured dots on their agent's tile (932b209, ADR-18)
- Agents report back with `fleet_report`; a report wakes an idle admiral, and `auto_close_done` closes agents whose work is merged (8280ba9, ADR-20)
- Agent mail: agents message each other once access is granted (cc09639, ADR-19)
