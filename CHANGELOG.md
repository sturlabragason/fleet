# What's new in fleet

User-facing changes, newest first. `fleet changes` and `Alt-g` show this file; it is built into the binary.

To add an entry: one line under today's `## YYYY-MM-DD` heading (add the heading if it is missing), at the top of that day, in the same commit as the change. Say what the user can do now, not how it was built. End with the ADR or commit in brackets when there is one: `(ADR-27)`, `(66a2ece, ADR-27)`.

The release notes are built from these lines (`scripts/release-notes.sh`), grouped by the commit type: `feat` is New, `fix` is Fixed, `test`/`ci`/`chore` is Internal. One change per line. Start the line with `**Changed default:**` when an existing setup behaves differently after the upgrade, and say how to keep the old behaviour; start it with `Contributors:` when only people working on fleet itself notice. Name only built-in profiles (`claude`, `copilot`, ...), never your own, and explain units and measurements a reader cannot check.

## 2026-11-22
- Every agent now gets a short guide for its own tool after the worker playbook: which models to run (and never run), how to delegate to subagents and how to prompt them, for `copilot`, `claude`, `agy`, `pi`, `vibe` and `kagent`. `agy` agents are told to wait on an async subagent instead of ending their turn. See it with `fleet playbook --profile <name>` (ADR-194)
- Custom and source builds on a `vX.Y.Z` release tag (with optional `+build` metadata) can now auto-upgrade to new releases via `[update] build_command` in `config.toml`, and `[update] wait_quiet = false` swaps a verified update right away without waiting for idle agents or interrupting running ones (ADR-191)
- `fleet burn` agents can no longer merge themselves or land in your own checkout: their done passes with the branch left for `--review`, a branch already waiting for review is not spawned again, `--profile` only picks from the `[burn] profiles` list, and a profile read through `ai-usagebar` with several accounts needs `account` set (ADR-190)
- `fleet burn` reads per-harness subscription quotas (`agy`, `pi`/NanoGPT, `claude` via `ai-usagebar`), sizes how many `+burn` tasks fit above a reserve using `runs.jsonl`, and logs or spawns worktree-only agents before reset (dry-run by default; `--tick` for a 30-minute systemd timer, `--review` for the morning Accept/Reject page) (ADR-190)
- `Alt-r` in fleet up replies to one earlier admiral message: pick it from the admiral's last 20 replies (type words to filter, or a todo or report id to quote that instead), and ⏎ puts it into the admiral's input box as a `> quote` under a `[re #N, time]` header, ready for your answer. Works with every admiral profile; one with no session log fleet reads offers the blocks on its screen (ADR-189)
- A fresh admiral's `fleet_brief` now lists today's asks and promises first, folds duplicates, keeps the newest pinned rules and recent notes, and points at the standing user rules; `fleet_brief file=todo` lists every open item. Closing an agent no longer turns its steers and `next:` lines into followups, re-listing an item in a handoff no longer files a copy, and another agent's untracked `result-*.md` no longer blocks a done (ADR-188)

## 2026-11-13
- A second admiral no longer gets stranded in another window: `fleet wall apply`, `fleet up` and `fleet up --monitors 1` move every admiral back under main in the left column (the pane moves, its process keeps running), one that did not fit comes back once the window is tall enough, a new `fleet admiral add` stacks under the last one, and `fleet wall admiral-hide|admiral-show NAME` (or `fleet_wall` `admiral_hide`/`admiral_show`) takes one out of the column and back (ADR-123).
- Agent processes can no longer eat the machine: fleet kills processes left behind by a closed, parked or crashed agent, parks an agent whose own processes grow past `[memory] agent_max` (default a quarter of RAM, swap included) or that burns more than `agent_max_cpu` cores while idle, tells the admiral, and `fleet doctor` lists leftovers under `orphans` (#48, ADR-122).
- The wall is quieter: an ACP agent's pane drops its header (the tmux border already names it), shows key hints only while it has focus and the rule above the input only when scrolled back, and redraws only the rows that changed, so busy panes no longer flicker (ADR-121).
- A `fleet_send` or a line typed into an ACP agent's pane reaches it at once while it is blocked in `fleet_wait`, for example waiting for an answer after a question report: the wait returns the prompt, so nobody has to press Esc to let it through (ADR-118).
- The admiral remembers where your recurring requests go: request routes in `~/.fleet/routes.toml` (dir, profile, effort, skill, permissions, prompt template) are listed in its brief, `fleet_spawn route=NAME` applies one, and when you correct it ("no, that goes to X") it saves the change with `fleet_route set`. See `examples/routes.toml.example` (#46, ADR-120).
