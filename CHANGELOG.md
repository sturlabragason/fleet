# What's new in fleet

User-facing changes, newest first. `fleet changes` and `Alt-g` show this file; it is built into the binary.

To add an entry: one line under today's `## YYYY-MM-DD` heading (add the heading if it is missing), at the top of that day, in the same commit as the change. Say what the user can do now, not how it was built. End with the ADR or commit in brackets when there is one: `(ADR-27)`, `(66a2ece, ADR-27)`.

The release notes are built from these lines (`scripts/release-notes.sh`), grouped by the commit type: `feat` is New, `fix` is Fixed, `test`/`ci`/`chore` is Internal. One change per line. Start the line with `**Changed default:**` when an existing setup behaves differently after the upgrade, and say how to keep the old behaviour; start it with `Contributors:` when only people working on fleet itself notice. Name only built-in profiles (`claude`, `copilot`, ...), never your own, and explain units and measurements a reader cannot check.

## 2026-11-12
- `fleet changes`, `Alt-g` and `fleet_changes` name the build you run (`fleet v1.22.0`, or `v1.22.0+pro.<sha>` for a pro build) instead of `fleet (unknown build)`.
- A wrapped link in the admiral pane now opens the whole URL even in a terminal that was attached before that fix: tmux gives OSC 8 links only to clients that attach after fleet turns them on, so the watcher now re-attaches older clients in place (one redraw) when it starts or moves onto a new release.

## 2026-11-11
- Windows install without admin: `irm https://raw.githubusercontent.com/sturlabragason/fleet/main/install.ps1 | iex`, or `scoop bucket add fleet https://github.com/sturlabragason/fleet` then `scoop install fleet/fleet`; Claude agents run through the npm-installed Claude ACP adapter, card checks run under `cmd` when there is no `sh`, and self-upgrade works there too (ADR-117).
- fleet runs on Windows: a portable `fleet-windows-amd64.exe` (and arm64) needs no tmux and runs every agent, Claude included, under the ACP driver, with spawn, send, status, peek, close and the admiral's MCP tools working as on Linux; the overview and wall stay Linux and macOS only (ADR-117).
- v1.19.0 is withdrawn: `go install` and `go get` skip it, and a release install on v1.19.0 upgrades to this release (retracted in go.mod).
- fleet upgrades itself: a release install checks for a new release every 6 hours, verifies it and swaps it in once no agent is working, and the admiral is told. `fleet update` shows the state, `--now` upgrades at once, and `[update] auto = false` in config.toml turns it off (ADR-114).
- "Add to wall", "Put in ▶ pane" and "Add as a new pane" on a parked agent (card menu, `Enter`, `a`, `fleet wall show/add`) wake it and show its pane, instead of doing nothing; when the memory guard refuses the wake, the message says so (#45).
- A `grants.json` that no longer parses no longer gives back mail access you revoked: mail between agents is refused, naming the file, until you repair it or move it aside (a copy is kept in `grants.json.broken`) (ADR-113).
- `fleet worktrees --prune` and `fleet branches --prune` keep the worktree and branch of an agent closed in the last 24 hours, so `fleet send --resume` can still bring it back (ADR-113).
- `fleet config explain <profile>` shows every setting a spawn of that profile gets and where it came from (`--driver`, `[profile.<name>]`, `[defaults]`, the tool profile or fleet's default), plus the `FLEET_*` variables set in your shell (ADR-113).
- fleet no longer replaces a `board.json` it cannot read with an empty board: it refuses to write and `fleet doctor` names the file. Closed agents' records moved to `~/.fleet/closed.json`, so the board the watcher rewrites every second is several times smaller; `fleet.log` rotates at 5 MB; transcripts of agents gone for over a week are removed; a hung tmux call or a crashing refresh no longer stops the watcher, and `fleet doctor` warns when it is stale (ADR-113).
- Agents can run any model their tool offers, not only Opus: `fleet spawn --model` and `model` on `fleet_spawn`/`fleet_squad_spawn` take any id, `fleet models <profile>` (or `fleet_profiles` with `profile`) lists what the tool offers, and a model the tool doesn't list is refused instead of silently swapped. Opus stays the default; `agy` agents can now pick a model too, `vibe` can't (ADR-112).
- A new fleet release now reaches the running fleet without detaching or running `fleet up`: the watcher re-applies tmux options, hooks and key bindings when it moves onto the new binary. Two things still wait: terminal features (such as hyperlink pass-through) apply at your next attach, and ACP agents keep the old host until parked and woken; the admiral is told which (ADR-111).
- A network outage (wifi drop, office move, VPN flap) no longer crashes or closes agents: the overview header shows `⊘ offline since HH:MM`, failed agents show `offline` instead of an error, new spawns wait in the queue, and the admiral gets one report when it starts and one when it ends. When the network is back, fleet sends `continue` to the agents that failed and restarts the ones whose host died, on their own session (ADR-110).
- The input box in an ACP agent's pane now edits like a terminal prompt: click to place the cursor, move with the arrows, Home/End and Ctrl/Alt word jumps, edit with Delete, Ctrl-W/U/K, add a line with Alt-Enter or Shift-Enter, recall sent lines with Up, and paste multi-line text at the cursor without it being sent (ADR-82).
- A link that wraps onto a second row in a fleet pane now opens the whole URL when clicked, in the admiral and in agent panes: fleet tells tmux to pass OSC 8 hyperlinks through to the terminal, and the ACP agent pane draws URLs and markdown links as OSC 8 links. Detach and run `fleet up` again to pick it up.
- **Changed default:** subagents of `claude` agents now run Opus like their agent, not Sonnet; an agent can still pick Sonnet for one scoped subtask, and `CLAUDE_CODE_SUBAGENT_MODEL = "sonnet"` in a profile's `env` brings back the old default. The admiral runs Opus too: `fleet up` refuses an admiral profile whose `args` name a model that is not Opus (ADR-100).

## 2026-11-10
- A report wake that Copilot did not submit no longer sits in the admiral's input box and blocks every later wake: fleet checks that Enter took, presses it again, and otherwise removes its line so the next poll retries. Only the watcher types wakes while it runs.
- Two monitors: `fleet up --monitors 2` keeps the admiral full screen in this terminal and opens the overview and wall full screen in a second terminal window (`fleet wall attach` opens it by hand). Wall keys work from both, and closing either window keeps every agent running; `fleet up --monitors 1` goes back to one window (ADR-108).
- `native_binary = true` on a Copilot profile in config.toml starts Copilot's native binary instead of its Node launcher, about 65 MB less per agent; it skips the launcher's version pick and auto-update, so update with `npm install -g @github/copilot`. Agents of one profile now get identical spawn arguments, and `claude` agents pass `--exclude-dynamic-system-prompt-sections`, so agents started close together share the cached prompt prefix.
- The main admiral can close another admiral with `fleet_admiral_close`, an admiral asks for another admiral's agent with `fleet_handover_request`, and `fleet admiral ls` shows each admiral's pane (#18).
- `fleet merge` no longer leaves a renumbered ADR's old entry and CHANGELOG line beside the new one when the renumber commit conflicts (#43).
- Release binaries and `SHA256SUMS` now carry GitHub build attestations: `gh attestation verify <file> -R sturlabragason/fleet` shows a download was built by fleet's release workflow, and `install.sh` runs that check itself when `gh` is installed and logged in (ADR-103).
- `fleet admiral restart` resumes the conversation you have now, also after `/clear`, and when an admiral's pane exits the main admiral gets a report (the main admiral's own exit shows on the status line) (ADR-101).
- Every fleet agent now runs Opus at every effort and as a leader, and plain `copilot` agents are pinned to `claude-opus-5.5` instead of the tool default. `fleet spawn --model` and `model` on `fleet_spawn`/`fleet_squad_spawn` pick another Opus model; a model that is not Opus is refused (ADR-100).
- After a fleet update changes the agent or admiral instructions, the next tool result says so once, and the new `fleet_instructions` tool returns the current text (ADR-102).
- A Claude or Copilot agent with a task that tries to stop without a done, blocked or question report is sent back once to call `fleet_report`, so it reports in the same turn instead of being flagged "no report" 20 s later; agents the user talks to are never sent back (ADR-105).
- `fleet exec -- go test ./...` runs a build or test for the current worktree on another machine (`[exec] host` in config.toml): it copies the worktree with rsync, runs over ssh and passes the output and exit code back; with no host it runs locally (ADR-107).
- `[memory] park_idle = "10m"` parks an agent that has been idle that long, freeing its process even when memory is fine; `fleet wake` resumes it (ADR-106).
- A working `claude` agent on the tmux driver now stays working instead of flipping to idle about once a second: fleet reads every frame of Claude's spinner, including `·` and `*`.
- The status line shows what each profile spent today (since midnight, closed agents included) as an estimated $ at list price, plus how much of your monthly Copilot AI-credit allowance (default 3,900, a Copilot Enterprise seat) fleet's agents have used, with any overage in $; it turns yellow at 80% and red at 100%. `fleet spend --today` shows the raw credits and tokens, and `[usage]` in config.toml sets the allowance and prices (ADR-97).
- Copilot agents, and Claude agents over ACP, now report status and subagents through hooks: fleet loads a per-agent plugin (`~/.fleet/plugins/<name>`) with `--plugin-dir` or the Claude adapter's session options, Claude's subagent dots work, and Claude over ACP gets the write fence (ADR-99).
- Contributors: one publisher at a time: `scripts/release-lock.sh` holds a lock in the shared git dir with the agent's name, and the release workflow refuses a commit that already has a version tag (ADR-73).
- With the watcher running, the overview no longer runs its own tmux commands every second: it reads one shared snapshot the watcher takes, which cuts its CPU from about 4.6 % to under 1 % of a core (ADR-98).
- Release pages are easier to scan: a headline, then Changed defaults / action needed, New, Changed and Fixed, one change per bullet, contributor-only items on one Internal line, and the design decisions (ADRs) linked at the bottom; the v1.0.0 to v1.10.0 pages were rewritten this way (ADR-73).
- A follow-up to an agent that closed (say after auto-close on `done`) is refused with when it closed; `fleet_send resume=true` or `fleet send --resume` brings it back on its last session with its task card, team and owner, then sends, queued if `max_working` is reached (#19, ADR-95).
- Pasting a large block into an ACP agent's pane lands at once, shown as `[Paste #1 +N lines]` in the input line until you press Enter, instead of redrawing for minutes (#42).
- The admiral costs less to keep running: reports that land within 30 s wake it once, it starts outside the fleet checkout so merges no longer reset its prompt cache, a Claude admiral keeps its cache for an hour, and it is told to hand off at 80k tokens of context; run `fleet admiral restart` to pick this up (ADR-93).
- A squad leader can pass `force=true` to `fleet_squad_send` to send past stale text in its own agent's input box, as the admiral can with `fleet_send`; an agent on a permission prompt is still refused (#20).
- `fleet doctor` checks your machine before `fleet up`: tmux 3.3 or newer, a UTF-8 locale, `~/.local/bin` on PATH, that config.toml and tools.toml parse, and that the admiral's and your own profiles' commands are found; one line per check with the fix, exit 1 on a fail, `--json` too (#23).
- Broadcasts and FYI agent mail no longer wake idle or done agents (a cold wake costs 20–26 AIC): they wait for the agent's next turn, `fleet_info` and `fleet_status` show the queued mail, and a direct ask still wakes its peer; mark a message with `needs_action` (`fleet mail send --act|--fyi`) to choose (ADR-92).
- Worker agents no longer load your global MCP servers, which cut a Copilot worker's first call from about 53k to 24k tokens here; `keep_mcp = ["name"]` in config.toml keeps one (ADR-91).
- `fleet report` prints its usage and files nothing when the text is empty or a flag such as `--help`, and `fleet_report` refuses an empty summary, so an agent probing flags no longer sends you a fake question (#5).
- `fleet_peek last_message=true` now works for Claude agents (read from their session transcript) and ACP agents, and for agy, vibe and other tools gives the end of the screen marked "(from the screen)" instead of an error (#16).
- `fleet spawn`, `fleet_spawn` and `fleet_squad_spawn` fail at once with a clear error when the dir does not exist or the profile's command is not on PATH, and `fleet up` does the same for the admiral's command, instead of reporting success and leaving a dead pane (#38, #23).
- An agent idle on a question it reported shows as waiting on the board and in `fleet_status` until it works again; after that its question or blocked report reads "(answered)" and stops counting as waiting on you, and `fleet_status` shows every report's age (ADR-90).
- `fleet merge` and `fleet merge --dry-run` stop when your branch's new ADR number is already on main or claimed by another agent, and tell you to take a new one with `fleet adr claim`, so a renumber no longer lands on someone else's number (ADR-50, fleet#40).
- Alt-Shift-X brings the wall back at once: the overview and agent panes are redrawn in well under a second instead of staying blank or torn for about 3 s, and Alt-x and preset changes are quicker too (#41, ADR-88).
- The admiral can now take over an ACP agent, check merge order (`fleet_touching`), list and prune worktrees and merged branches (after your yes), start another admiral and tell you what's new; its rules list every tool, and a Claude admiral now gets all of them instead of a cut-off copy (ADR-86).
- Agent branches no longer pile up on GitHub: closing an agent deletes its pushed `fleet/<name>` once it is merged into main, and `fleet branches --prune` deletes the other merged ones no agent is on (ADR-87).
- ACP agent panes are easier to read: a header with the agent's name, profile and status, each tool call on one line whose ○/✓/✗ updates in place, thoughts dimmed and folded, markdown rendered, text wrapped to the pane and reflowed on resize, your prompts marked with a coloured `›`, and the keys shown under the input line; colours follow your fleet theme and `NO_COLOR` is honoured. PgUp/PgDn scroll. Park and wake a running ACP agent to get it (ADR-85).
- A second admiral you shrink stays that size when you click tiles, change the wall or hide and show the admirals; `fleet admiral min <name>` minimizes one admiral pane or restores it (ADR-84).
- fleet's own tests and the screenshot script no longer leave tmux servers or `fleet watch` processes running (ADR-83).
- You can work with an ACP agent directly in its pane: type a prompt at the `›` line, answer a question with its number, press Esc to cancel the turn, and Ctrl-T or `fleet takeover <name>` to continue the same session in the tool's own screen (`--acp` hands it back); the admiral won't send over you while you do (ADR-82).
- Nothing in fleet blinks or animates any more: tiles show one static dot per state (○ working, ● waiting), and the unread-report badge is a quiet `● main 8` that no longer flashes on and off; a leaked test process can no longer reach your fleet server (ADR-81).

- `fleet worktrees` lists the leftover agent worktrees with size, merged and dirty state; `--prune` removes the merged, clean ones and never touches uncommitted work (ADR-79).

## 2026-11-09
- `fleet version` says which release you are running, and releases now ship macOS binaries (amd64, arm64) next to linux ones, with `SHA256SUMS` (ADR-73).
- Give an agent standing permissions on its task card: `may` on `fleet_spawn` and `fleet_squad_spawn` (for example merge-local, push-main, deploy) tells it what it may do without asking, and `fleet_info` shows them (#32).
- Agents on one repo can message a squad leader there without asking first, so a hand-off to another team's lead no longer goes through you. A refused message names the lead the sender may message instead (#35).
- `fleet_send` and `fleet_squad_send` to an agent still in the queue hold the text and deliver it when the agent starts, instead of failing. A leader's `fleet_squad_close confirmed=true` closes on the first call (#33).
- Every `fleet_spawn`, `fleet_squad_spawn` and `fleet spawn` reply names the profile and model the agent got, and a queued one says how many are ahead of it. Set `[defaults] profile` in `config.toml` and spawn calls may leave out the profile (#31).
- See how often each Copilot agent compacted its context (`⟲2` after its spend in `fleet_status`, `fleet spend` and `fleet info`), and the admiral or squad leader is told once to hand an agent over to a fresh one after 2 compactions or 1,000 AIC; set `recycle_compactions` / `recycle_aic` in config.toml, 0 turns them off (ADR-71, #27).
- Wait for reports without polling: the admiral and squad leaders call `fleet_wait` (agents: a peer's reply), and a shell runs `fleet wait [--agents a,b] [--timeout 300s]`; it returns the moment a new report or message arrives, or says nothing came (exit 2) (ADR-72).
- Admirals no longer burn turns on autopilot "not complete yet" nudges: a Copilot admiral always starts in interactive mode, and agents are told to load the fleet tools once at the start and end with one report (ADR-70, #28, #29, #34).
- Parking or closing an agent also stops the processes its CLI started (a Copilot voice server, a build), so they no longer keep running and holding memory after the agent is gone (ADR-44, #26).
- Agents that share a dir without worktrees of their own no longer overwrite each other's result file: each is told to write `result-<name>.md`, and a result file left over from before the spawn no longer shows as written (#17).
- An agent's own result file (`result.md` or the card's) no longer blocks auto-close, adds an "uncommitted changes" close note, counts in `fleet_info`'s git dirty, or shows as an overlap in `fleet touching` and `fleet merge` (#11).
- Read one agent's result without wading through the rest: `fleet_reports name=<agent>` returns only its reports and leaves the others unread, `all=true` lists one headline per report instead of every full text, and task cards are shown only for the agents in the result.
- An agent whose screen is still changing is no longer reported to its owner as "stopped mid-task without a report", even if its status reads idle (an agy agent editing files did this) (ADR-68, #12).
- Agents no longer all read `gone` when fleet runs without a UTF-8 locale (`LANG` unset or `C`, as in `env -i`, cron or minimal containers): fleet now always talks to tmux in UTF-8 mode (#21).
- Agents no longer run the full test suite on your machine: they test only the packages they changed, push their own `fleet/<name>` branch and merge once GitHub Actions (build, vet, full tests and `-race`) is green on it (ADR-69).
- Agents you talk to directly also show when they stop mid-turn without reporting ("Logging everything now.", then nothing): a muted `…` on the tile and wall border once you stop typing, and "no report, the user's" in `fleet_status`. The admiral is not woken for them (ADR-68, #8).
- The board shows Copilot agents as working while they work: Copilot CLI 1.0.107's new busy footer ("ctrl+c interrupt") was being read as idle (ADR-68).
- See which agents stopped mid-task without reporting: they get `…` on their tile and wall border, "idle (no report)" in `fleet_status`, and the admiral is told once per task. The "unread reports" note on admiral results now names the newest reports (ADR-68).
- Clear the wall in one step: `Alt-X` takes every agent pane off it (the agents keep running), and `Alt-X` again puts them back. Also `fleet wall hide-all|restore` and the admiral's `fleet_wall` `hide_all|restore` (ADR-67).
- Ask the admiral for a design, code, research or an opinion and it spawns an agent for it straight away instead of drafting the answer in chat; it asks you to confirm the exact target before an agent files into an external tracker such as ADO or Jira (#3).

## 2026-11-06
- Fleet state holds up across versions: every file under `~/.fleet` (board, teams, grants, ADR claims, admiral session) keeps fields an older or newer fleet wrote instead of dropping them, an idle fleet no longer rewrites `board.json` every second, `fleet watch` re-execs itself when `bin/fleet` is rebuilt and only one can ever run, and `fleet up` replaces a watcher left on an old binary. `fleet note --pin` (or `pin: true` on `fleet_note`) keeps a standing rule in every `fleet_brief` instead of letting it scroll out after 30 notes. Restart the fleet once for this to take effect (ADR-62)
- Fleet keeps out of a session you are talking to: `fleet spawn --interactive` (or `interactive: true` on `fleet_spawn`) marks an agent as yours, so it is never auto-closed and reports progress instead of done until you end the session. Fleet also notices by itself when you type in an agent's pane and marks it `✎`. While you are typing there, or have an interactive agent's pane open, or have unsent text in its box, `fleet_send` and `fleet send` refuse to type over you unless forced (`force: true`, `--force`) (fleet#1, ADR-61)
- Copilot agents start with about 40% less context: the `copilot` and `claude-copilot` profiles now leave out the built-in tools no fleet agent uses (workflows, the session database, memory, canvas, schedules, the built-in GitHub MCP), and `light` and `standard` agents also go without subagents. - Safer agents and squads: every effort level, `light` included, now tells the agent never to push, to credit AI with `Assisted-by:` and never a `Co-authored-by:`, to edit nothing on a read-only task and to commit on its own `fleet/` branch, never main. Closing a squad leader hands its squad's unread reports to you instead of dropping them, leaves a team of yours with the same name alone, a peer message no longer swallows a squad report's wake, and a leader's `fleet close/send/park/wake` act only on its own squad (ADR-59)
